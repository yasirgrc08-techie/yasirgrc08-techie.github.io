# Build a Resume and GitHub Portfolio / Learning Roadmap

By Yasir Sharfi

## The Idea

Should I include every technology I have tried?

A useful portfolio answers three questions: what problem did you solve, what did you personally build, and how can someone verify it? Align the resume, repository, demo, and interview narrative so a reviewer sees one consistent, defensible story.

## Visual Blueprint

1. **Build the mental model**: Order projects and experience by fit to the target role, not by the number of tools used.
2. **Phase 1 / Days 1-3**: Inventory public repositories, links, deployment status, and resume claims.
3. **Phase 2 / Days 4-7**: Write setup instructions and sample data. Pin important dependency versions, explain environment variables without values, and add a small automated test command.
4. **Phase 3 / Week 2**: Add meaningful tests, one design decision record, and a measured improvement if justified.
5. **Phase 4 / Week 3**: Check mobile presentation, accessibility, downloads, and all links. Rehearse a project walkthrough and answer why you chose the design.
6. **Prove readiness**: All links and setup instructions have been checked.
