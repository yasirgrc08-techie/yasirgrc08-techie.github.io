# Build a Resume and GitHub Portfolio / Practice Decisions

By Yasir Sharfi

## The Idea

Should I include every technology I have tried?

A useful portfolio answers three questions: what problem did you solve, what did you personally build, and how can someone verify it? Align the resume, repository, demo, and interview narrative so a reviewer sees one consistent, defensible story.

## Visual Blueprint

1. **Lead with relevance**: Order projects and experience by fit to the target role, not by the number of tools used.
2. **Watch for**: Publishing secrets or assuming deletion removes them from history.
3. **Make claims falsifiable**: Explain the workload and measurement behind any speed or reliability improvement. If there was no measurement, describe the functional change honestly.
4. **Watch for**: Calling a local demo highly scalable without a workload or evidence.
5. **A README is part of the product**: Include purpose, prerequisites, setup, sample input, expected output, tests, architecture, and known limitations.
6. **Watch for**: Using generic AI-generated claims that do not match the repository.
