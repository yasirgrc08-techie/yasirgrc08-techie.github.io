# Run Better Mocks and Measure Readiness / Learning Roadmap

By Yasir Sharfi

## The Idea

What score means I am ready?

A mock is a diagnostic experiment. It should reveal how you clarify, reason, implement, test, communicate, and recover from feedback. Score these dimensions separately, then change one behavior and check it on a new task. A single pass or failure is not a reliable verdict.

## Visual Blueprint

1. **Build the mental model**: Choose an unseen problem or change the constraints of a known one. Hide the pattern category.
2. **Phase 1 / Week 1**: Run one coding mock and one role-relevant project or design discussion. Use the expected tools, but do not assume one universal employer timing.
3. **Phase 2 / Week 2**: If recognition is weak, compare related patterns; if implementation is weak, rebuild small primitives; if testing is weak, practice adversarial examples.
4. **Phase 3 / Week 3**: Run a mixed coding set and an architecture discussion with changing requirements. Ask the reviewer to interrupt with a legitimate constraint or failing test.
5. **Phase 4 / Week 4**: Review recent sessions, not the best historical one. Keep strengths warm and revisit persistent gaps. Confirm the actual interview scope and logistics.
6. **Prove readiness**: Recent mocks use unfamiliar tasks and recorded hints.
