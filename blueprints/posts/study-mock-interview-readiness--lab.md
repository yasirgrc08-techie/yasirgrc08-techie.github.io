# Run Better Mocks and Measure Readiness / Build and Validate

By Yasir Sharfi

## The Idea

What score means I am ready?

A mock is a diagnostic experiment. It should reveal how you clarify, reason, implement, test, communicate, and recover from feedback. Score these dimensions separately, then change one behavior and check it on a new task. A single pass or failure is not a reliable verdict.

## Visual Blueprint

1. **Set up the scenario**: Across three mocks, the candidate finds good algorithms but declares completion without testing. Two solutions contain boundary bugs.
2. **Experiment 1**: Add a visible completion checklist: normal case, empty or minimal case when allowed, duplicates or ties, and a boundary condition specific to the invariant.
3. **Experiment 2**: Practice tracing the smallest input that stresses each update rule.
4. **Experiment 3**: Run a new mock and ask the reviewer to score testing separately.
5. **Expected evidence**: The intervention targets a repeated observable behavior.
6. **Check the result**: Are hints and independent discoveries recorded separately?
