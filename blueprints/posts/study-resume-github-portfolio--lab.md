# Build a Resume and GitHub Portfolio / Build and Validate

By Yasir Sharfi

## The Idea

Should I include every technology I have tried?

A useful portfolio answers three questions: what problem did you solve, what did you personally build, and how can someone verify it? Align the resume, repository, demo, and interview narrative so a reviewer sees one consistent, defensible story.

## Visual Blueprint

1. **Set up the scenario**: A repository says 'scalable URL shortener using modern technologies' but contains no workload, tests, or discussion of collisions.
2. **Experiment 1**: Define create-link, redirect, and expiration behavior. State the storage model and what a collision means.
3. **Experiment 2**: Add tests for duplicate aliases, malformed destinations, missing links, and expired links.
4. **Experiment 3**: Write a decision note comparing random IDs with sequential encoding and explaining abuse controls and redirect semantics.
5. **Expected evidence**: The project becomes credible because its behavior, evidence, and limitations are visible.
6. **Check the result**: Do README commands work in a clean environment?
