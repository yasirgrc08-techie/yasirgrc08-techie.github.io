LRU Cache
LLD
GoogleAmazonMicrosoft
→

Problem

Design a Least Recently Used cache with O(1) get and put operations.

Design

DATA STRUCTURE: ┌─────────────────────────────────────────────────────────┐ │ HashMap: { key → Node pointer } O(1) lookup │ │ │ │ Doubly Linked List: HEAD ↔ [A] ↔ [B] ↔ [C] ↔ TAIL │ │ (LRU) (MRU) │ │ │ │ get(B): remove B from middle, move to tail (MRU) │ │ put(D): add at tail. If full, evict HEAD.next (LRU) │ └─────────────────────────────────────────────────────────┘ class Node: def __init__(self, key, val): self.key, self.val = key, val self.prev = self.next = None class LRUCache: def __init__(self, capacity): self.cache = {} # key → Node self.cap = capacity self.head = Node(0,0) # dummy self.tail = Node(0,0) # dummy self.head.next = self.tail self.tail.prev = self.head def _remove(self, node): # O(1) node.prev.next = node.next node.next.prev = node.prev def _add(self, node): # O(1) — add before tail node.prev = self.tail.prev node.next = self.tail self.tail.prev.next = node self.tail.prev = node def get(self, key): # O(1) if key in self.cache: node = self.cache[key] self._remove(node) self._add(node) return node.val return -1 def put(self, key, val): # O(1) if key in self.cache: self._remove(self.cache[key]) node = Node(key, val) self._add(node) self.cache[key] = node if len(self.cache) > self.cap: lru = self.head.next self._remove(lru) del self.cache[lru.key]

Key Decisions

Why DLL?Need O(1) removal from middle. Array can't do this. DLL + HashMap = O(1) for everything
Dummy NodesHead and tail sentinels eliminate null checks at boundaries. Cleaner code
Thread SafetyFor concurrent use: ReadWriteLock or ConcurrentHashMap + synchronized DLL ops
EvictionAlways evict head.next (oldest). Python alternative: collections.OrderedDict
